## Overview

Terraform manages all infrastructure across all clouds and accounts. The design follows these principles:

1. **Pure IaC**: All infrastructure is code. Zero manual steps.
2. **Modular**: Each module is self-contained, reusable, and independently testable.
3. **Composable**: Modules compose to form environments (dev, staging, prod).
4. **Provider-Agnostic**: Core modules abstract cloud-specific details.
5. **Remote State**: All state is stored remotely with locking.
6. **Cross-Account**: Modules assume roles across accounts for centralized management.

```
terraform/
├── modules/
│   ├── aws/
│   │   ├── network/          # VPC, subnets, TGW, NAT, VPN
│   │   ├── eks/              # EKS cluster, node groups, add-ons
│   │   ├── irsa/             # IAM roles for service accounts
│   │   ├── storage/          # S3 buckets, EFS, PVC
│   │   ├── dns/              # Route53 zones, records
│   │   └── registry/         # ECR repositories
│   ├── gcp/
│   │   ├── network/          # VPC, subnets, Cloud VPN, Shared VPC
│   │   ├── gke/              # GKE cluster, node pools
│   │   ├── storage/          # GCS buckets
│   │   └── dns/              # Cloud DNS zones
│   └── cross-cloud/
│       ├── vpn/              # AWS <-> GCP VPN, BGP
│       ├── dns/              # Cross-cloud DNS replication
│       └── monitoring/       # Cross-cloud observability
│
├── envs/
│   ├── dev/
│   │   ├── aws-network.tf    # Call network module for dev
│   │   ├── aws-eks.tf        # Call EKS module for dev
│   │   ├── providers.tf      # Provider configurations
│   │   ├── variables.tf      # Variables
│   │   ├── outputs.tf        # Outputs
│   │   └── terraform.tfvars  # Values (generated by config)
│   ├── staging/              # Same structure
│   └── prod/                 # Same structure
│
├── bootstrap/                # Bootstrap code
│   ├── main.tf               # Creates S3 bucket + DynamoDB
│   ├── outputs.tf
│   └── setup.sh              # Script to run bootstrap
│
└── scripts/
    ├── generate-config.py     # Generate tfvars from YAML config
    ├── apply-all.sh           # Apply environments in order
    └── destroy-all.sh         # Destroy environments in reverse order
```

## Provider Configuration

Each environment directory has a `providers.tf` that configures all providers:

```hcl
# terraform/envs/dev/providers.tf

terraform {
  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.0"
    }
    google = {
      source  = "hashicorp/google"
      version = "~> 6.0"
    }
    kubernetes = {
      source  = "hashicorp/kubernetes"
      version = "~> 2.0"
    }
    helm = {
      source  = "hashicorp/helm"
      version = "~> 2.0"
    }
    random = {
      source  = "hashicorp/random"
      version = "~> 3.0"
    }
  }
  backend "s3" {
    # Configured per environment (see State Management)
  }
}

# --- AWS Providers ---

# AWS: Network Account (Hub)
provider "aws" {
  alias  = "aws-network"
  region = var.aws_network_region
  assume_role {
    role_arn = "arn:aws:iam::${var.aws_network_account_id}:role/TerraformDeployer"
  }
  default_tags {
    tags = var.tags
  }
}

# AWS: Workload Account (Dev)
provider "aws" {
  alias  = "aws-workload-dev"
  region = var.aws_workload_region
  assume_role {
    role_arn = "arn:aws:iam::${var.aws_workload_dev_account_id}:role/TerraformDeployer"
  }
  default_tags {
    tags = var.tags
  }
}

# AWS: Shared Services Account
provider "aws" {
  alias  = "aws-shared"
  region = var.aws_shared_region
  assume_role {
    role_arn = "arn:aws:iam::${var.aws_shared_account_id}:role/TerraformDeployer"
  }
  default_tags {
    tags = var.tags
  }
}

# --- GCP Provider (Multi-Cloud) ---

provider "google" {
  alias       = "gcp"
  project     = var.gcp_project_id
  region      = var.gcp_region
  impersonate_service_account = var.gcp_impersonate_sa
}

# --- Kubernetes Providers ---

provider "kubernetes" {
  alias        = "k8s-dev"
  host         = module.aws-eks-dev.cluster_endpoint
  cluster_ca_certificate = base64decode(module.aws-eks-dev.cluster_ca_cert)
  exec {
    api_version = "client.authentication.k8s.io/v1beta1"
    command     = "aws"
    args        = ["eks", "get-token", "--cluster-name", module.aws-eks-dev.cluster_name]
  }
}

provider "helm" {
  alias  = "helm-dev"
  kubernetes {
    host         = module.aws-eks-dev.cluster_endpoint
    cluster_ca_certificate = base64decode(module.aws-eks-dev.cluster_ca_cert)
    exec {
      api_version = "client.authentication.k8s.io/v1beta1"
      command     = "aws"
      args        = ["eks", "get-token", "--cluster-name", module.aws-eks-dev.cluster_name]
    }
  }
}
```

## AWS Modules

### `modules/aws/network`

```
modules/aws/network/
├── main.tf
├── variables.tf
├── outputs.tf
└── README.md
```

**Purpose**: Creates VPC, subnets, Internet Gateway, NAT Gateway, Transit Gateway.

**Inputs**:

| Variable | Type | Description | Required |
|----------|------|-------------|:--------:|
| `vpc_cidr` | `string` | VPC CIDR block | Y |
| `azs` | `list(string)` | Availability zones | Y |
| `public_subnets` | `list(string)` | Public subnet CIDRs | Y |
| `private_subnets` | `list(string)` | Private subnet CIDRs | Y |
| `enable_nat_gateway` | `bool` | Deploy NAT Gateway | N |
| `single_nat_gateway` | `bool` | Single NAT for all AZs | N |
| `enable_transit_gateway` | `bool` | Create TGW | N |
| `tgw_share_accounts` | `list(string)` | Accounts to share TGW with | N |
| `tags` | `map(string)` | Resource tags | N |

**Outputs**:

| Output | Description |
|--------|-------------|
| `vpc_id` | VPC ID |
| `public_subnet_ids` | Public subnet IDs |
| `private_subnet_ids` | Private subnet IDs |
| `transit_gateway_id` | TGW ID (if created) |
| `transit_gateway_ram_arn` | RAM share ARN for TGW |
| `nat_gateway_ips` | NAT Gateway EIPs |

**Key design decisions**:
- Hub account owns the Transit Gateway and shares via RAM
- Spoke accounts attach their VPCs to the shared TGW
- Separate subnets for system, GPU-inference, GPU-batch workloads
- Flow logs enabled and sent to centralized S3/CloudWatch

### `modules/aws/eks`

```
modules/aws/eks/
├── main.tf
├── variables.tf
├── outputs.tf
├── nodegroup-system.tf
├── nodegroup-gpu.tf
├── karpenter.tf
├── irsa.tf
└── README.md
```

**Purpose**: Creates EKS cluster with managed node groups and Karpenter.

**Inputs**:

| Variable | Type | Description | Required |
|----------|------|-------------|:--------:|
| `cluster_name` | `string` | EKS cluster name | Y |
| `cluster_version` | `string` | K8s version | Y |
| `vpc_id` | `string` | VPC ID | Y |
| `subnet_ids` | `list(string)` | Subnet IDs for cluster | Y |
| `system_node_group` | `object` | System node group config | Y |
| `gpu_node_groups` | `list(object)` | GPU node group configs | N |
| `enable_karpenter` | `bool` | Enable Karpenter | N |
| `enable_irsa` | `bool` | Create IRSA roles | N |
| `cluster_endpoint_public_access` | `bool` | Public cluster endpoint | N |
| `cluster_endpoint_private_access` | `bool` | Private cluster endpoint | Y |
| `tags` | `map(string)` | Tags | N |

**Outputs**:

| Output | Description |
|--------|-------------|
| `cluster_endpoint` | EKS cluster endpoint |
| `cluster_ca_cert` | Cluster CA certificate |
| `cluster_name` | Cluster name |
| `cluster_arn` | Cluster ARN |
| `karpenter_iam_role_arn` | Karpenter node role |
| `oidc_provider_arn` | OIDC provider for IRSA |
| `oidc_provider_url` | OIDC issuer URL |

**Key design decisions**:
- System node group: t3.medium, 2-5 nodes, spot, no GPUs
- GPU node groups: T4/A10 for inference, H100 for batch
- Karpenter provisions GPU nodes dynamically
- Cluster endpoint is private (no public access)
- EKS control plane logs sent to CloudWatch
- IRSA roles created per service account
- Security groups restrict intra-cluster traffic

Same interface as `aws/network` but for GCP:

## Cross-Cloud Modules

### `modules/cross-cloud/vpn`

**Purpose**: Establishes a site-to-site VPN between AWS and GCP for multi-cloud networking.

```
modules/cross-cloud/vpn/
├── main.tf
├── aws-side.tf
├── gcp-side.tf
├── variables.tf
├── outputs.tf
└── README.md
```

```hcl
# Pseudocode for cross-cloud VPN

# AWS Side
resource "aws_vpn_connection" "cross_cloud" {
  provider           = aws.aws-network
  customer_gateway_id = aws_customer_gateway.gcp.id
  transit_gateway_id  = aws_ec2_transit_gateway.main.id
  type                = "ipsec.1"
  tunnel1_preshared_key = random_password.tunnel1.result
  tunnel2_preshared_key = random_password.tunnel2.result
}

# GCP Side
resource "google_compute_vpn_tunnel" "aws_side" {
  provider      = google.gcp
  name          = "to-aws-tunnel-1"
  peer_ip       = aws_vpn_connection.cross_cloud.tunnel1_address
  shared_secret = random_password.tunnel1.result
  target_vpn_gateway = google_compute_vpn_gateway.main.id
}

resource "google_compute_router_peer" "bgp_peer" {
  provider                = google.gcp
  name                    = "bgp-aws-tunnel-1"
  router                  = google_compute_router.main.name
  peer_ip_address         = aws_vpn_connection.cross_cloud.tunnel1_bgp_peer_address
  peer_asn                = aws_vpn_connection.cross_cloud.tunnel1_bgp_asn
  interface               = google_compute_router_interface.bgp_tunnel1.name
}
```

## Dependency Ordering

### Apply Order (Bottom-Up)

```
Step 1: Bootstrap
  └── Create S3 + DynamoDB (runs once, in any account)

Step 2: Network Account (Hub)
  └── terraform/envs/dev/ (target: aws-network)
      ├── VPC + subnets + NAT
      ├── Transit Gateway
      ├── Route53 zones
      └── CloudWatch + flow logs

Step 3: Shared Services Account
  └── terraform/envs/dev/ (target: aws-shared)
      ├── Harbor (via Terraform + Helm)
      ├── Vault backend
      └── ECR repositories

Step 4: Workload Account (Spoke)
  └── terraform/envs/dev/ (target: aws-workload)
      ├── VPC (connected to hub TGW)
      ├── EKS cluster
      ├── Node groups + Karpenter
      ├── IRSA roles
      └── GPU node configuration

Step 5: GCP (if multi-cloud)
  └── terraform/envs/dev/ (target: gcp)
      ├── Shared VPC
      ├── GKE cluster
      └── Cloud DNS

Step 6: Cross-Cloud (if multi-cloud)
  └── terraform/envs/dev/ (target: cross-cloud)
      ├── VPN tunnels
      ├── BGP routing
      └── DNS sync
```

### Destroy Order (Top-Down, Reverse)

```
Cross-Cloud → GCP → Workload Spoke → Shared Services → Network Hub
```

## Environment Layering

```
config/demo.yaml
       │
       ▼
generate-config.py
       │
       ├──▶ terraform/envs/dev/terraform.tfvars
       ├──▶ terraform/envs/staging/terraform.tfvars
       └──▶ terraform/envs/prod/terraform.tfvars
```

Each environment gets:
- Its own Terraform state (S3 key prefix per env)
- Its own config overrides via `values/{env}.yaml`
- Its own VPC/subnets (dev can be smaller, prod is HA)
- Its own EKS cluster (dev can be single-node, prod is multi-AZ)

## Bootstrap Process

```bash
# Step 1: Initialize Git
git init
git add .
git commit -m "Initial commit"

# Step 2: Run bootstrap
./terraform/bootstrap/setup.sh
# Creates:
#   - S3 bucket for Terraform state
#   - DynamoDB table for state locking
#   - KMS key for state encryption

# Step 3: Generate config from YAML
./terraform/scripts/generate-config.py config/demo.yaml
# Generates:
#   - terraform/envs/dev/terraform.tfvars
#   - ... (other derived files)

# Step 4: Apply in dependency order
./terraform/scripts/apply-all.sh --env dev --auto-approve
```

### Bootstrap Script (`terraform/bootstrap/setup.sh`)

```bash
#!/bin/bash
# Creates the S3 backend and DynamoDB lock table
# Uses the network account for centralized state management

set -euo pipefail

ACCOUNT_ID=$(aws sts get-caller-identity --query Account --output text)
BUCKET="ai-platform-tfstate-${ACCOUNT_ID}"
TABLE="ai-platform-tfstate-lock"
REGION="${AWS_REGION:-us-west-2}"

# Create S3 bucket (with encryption)
if ! aws s3api head-bucket --bucket "$BUCKET" 2>/dev/null; then
  aws s3api create-bucket \
    --bucket "$BUCKET" \
    --region "$REGION" \
    --create-bucket-configuration LocationConstraint="$REGION"
  
  aws s3api put-bucket-encryption \
    --bucket "$BUCKET" \
    --server-side-encryption-configuration '{"Rules":[{"ApplyServerSideEncryptionByDefault":{"SSEAlgorithm":"AES256"}}]}'
  
  aws s3api put-bucket-versioning \
    --bucket "$BUCKET" \
    --versioning-configuration Status=Enabled
  
  echo "Created S3 bucket: $BUCKET"
fi

# Create DynamoDB table (with encryption)
if ! aws dynamodb describe-table --table-name "$TABLE" 2>/dev/null; then
  aws dynamodb create-table \
    --table-name "$TABLE" \
    --attribute-definitions AttributeName=LockID,AttributeType=S \
    --key-schema AttributeName=LockID,KeyType=HASH \
    --billing-mode PAY_PER_REQUEST \
    --region "$REGION"
  
  echo "Created DynamoDB table: $TABLE"
fi

echo "Bootstrap complete!"
echo "Bucket:  $BUCKET"
echo "Table:   $TABLE"
echo "Region:  $REGION"
```

## Key Design Patterns

### 1. Tag Propagation

All resources get consistent tags from a single source:

```hcl
# terraform/envs/dev/variables.tf
variable "tags" {
  type = map(string)
  default = {
    Environment = "dev"
    ManagedBy   = "terraform"
    Project     = "ai-platform"
    CostCenter  = "platform-engineering"
  }
}
```

### 2. Module Versioning

Modules are versioned with Git tags and referenced by tag:

```hcl
module "network" {
  source = "git::https://github.com/you/ai-platform.git//terraform/modules/aws/network?ref=v0.1.0"
  # ...
}
```

### 3. Config-Driven Code Generation

The `generate-config.py` script reads `config.yaml` and produces:

- `terraform/envs/{env}/terraform.tfvars` — Environment variables
- `terraform/envs/{env}/providers-override.tf` — Dynamic provider config
- `terraform/envs/{env}/account-config.tf` — Account definitions

This means changing a provider or region is just a config change, not a code change.

### 4. Zero-Default Security

Every security group, IAM policy, and network ACL starts empty. Access is explicitly granted:

```hcl
resource "aws_security_group" "eks_cluster" {
  name        = "eks-cluster-sg"
  description = "Security group for EKS cluster"
  vpc_id      = var.vpc_id
  
  # No default rules — all traffic must be explicitly allowed
  
  tags = var.tags
}

# Explicit ingress rules only
resource "aws_vpc_security_group_ingress_rule" "api_server" {
  security_group_id = aws_security_group.eks_cluster.id
  cidr_ipv4         = var.vpc_cidr  # Only from VPC
  from_port         = 443
  to_port           = 443
  ip_protocol       = "tcp"
}
```
